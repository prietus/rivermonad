# Development

```sh
git clone https://github.com/prietus/rivermonad
cd rivermonad
cabal build
cabal test
```

Try changes without leaving your session by running river nested inside
your current compositor: `river -c rivermonad` from a terminal.
`RIVERMONAD_DEBUG=1` logs every Wayland event to stderr.

## Layout of the source

| | |
|---|---|
| `src/Rivermonad/Core.hs` | the types: `X`, `XConfig`, `XState`, `LayoutClass`, messages, `ExtensibleState` |
| `src/Rivermonad/StackSet.hs` | xmonad's `StackSet` |
| `src/Rivermonad/Engine.hs` | river's events: windows, outputs, seats, the manage and render sequences, placing windows |
| `src/Rivermonad/Main.hs` | start-up, the main loop, restarts |
| `src/Rivermonad/Operations.hs` | the actions configurations use: `windows`, `spawn`, `sendMessage`... |
| `src/Rivermonad/IPC.hs` | the IPC socket |
| `src/Rivermonad/Wayland/` | the wire protocol and the generated bindings |
| `src/Rivermonad/{Actions,Hooks,Layout,Util}/` | the contrib modules |
| `protocol/` | river's protocol XML files (from river v0.5.0) |

## The protocol bindings

`Rivermonad/Wayland/Protocol.hs` is generated from `protocol/*.xml`:

```sh
tools/regen.sh
```

## How it runs

river sends the window manager a *manage sequence* whenever windows,
outputs or seats change; rivermonad updates its `StackSet`, runs the manage
hook for new windows, the queued actions (key presses, IPC actions) and the
log hook, then answers with where every window goes. Key bindings are
registered with river and arrive as events. State changes made outside a
manage sequence are applied in the next one: `queue` asks river for one.

## Porting a module

Most xmonad-contrib modules port by renaming `XMonad` to `Rivermonad` and
replacing X11 calls: window properties become `WindowInfo` fields
(`wiAppId`, `wiTitle`, `wiPid`...), `dmenu` calls become the non-blocking
[`Dmenu`](modules/util/Dmenu.md). Document the module in its header comment
with `-- >` examples: the [module pages](modules/index.md) of this site are
generated from it.

## This site

The pages are in `wiki/docs/`, the module pages are generated by
`tools/wiki/gen-modules.py`, and `tools/wiki/publish.sh` builds the site
